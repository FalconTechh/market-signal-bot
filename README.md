# NexCandle AI PRO V19 — Ultra Pro Market Session Build


This build focuses on **fail-safe operation**, not a false promise of guaranteed market availability or guaranteed prediction accuracy.

## V11 resilience upgrades
- Smart provider failover with the configured provider order.
- Automatic bounded retries for transient provider/network failures.
- Immediate provider cooldown on quota/rate-limit/auth failures.
- Last-successful-provider preference per pair/timeframe.
- Single-flight locking to prevent many users from hammering the same API.
- In-memory candle cache plus SQLite recovery cache.
- Recovery of recent validated candles after process restart when deployment storage is persistent.
- Recently confirmed directional recovery during a short provider outage, explicitly marked `RECOVERY` rather than presented as fresh live data.
- Completed-candle validation before analysis.
- Existing multi-timeframe analysis and adaptive regime-aware ensemble retained.
- Telegram webhook remains Render-safe; polling is not used on Render.
- User-facing provider/API errors remain hidden.

## Important
No market-data system can honestly guarantee that it will **never** experience a provider outage, network outage, Render restart, or stale feed. This build is designed so those failures are isolated, retried, bypassed, cached, and recovered from where possible instead of crashing the bot or inventing a signal.

### Recommended Render variables
Keep the existing API keys and settings. Useful resilience controls include:

- `DATA_PROVIDER_ORDER=dukascopy,biquote,twelvedata,finnhub,alphavantage,yahoo2,yahoo`
- `PROVIDER_RETRY_LIMIT=3`
- `PROVIDER_TIMEOUT_SECONDS=10`
- `ALLOW_STALE_CANDLE_FALLBACK=true`
- `PERSISTED_CACHE_MAX_AGE=21600`
- `RECOVERY_MAX_AGE=900`

For durable restart recovery, use persistent Render storage for the SQLite database path. Without persistent storage, the live in-process cache and provider failover still work, but a full restart clears SQLite recovery data.

## V21 Secure Feed / Fast Unlock
- Set `NEXCANDLE_ACCESS_CODE` to any 4-digit code in Render Environment.
- `FLASK_SECRET_KEY` is generated by Render so the unlock session remains valid across requests.
- The access lock protects `/api/premium-signal` only; market-status and feed/provider operations are not treated as password failures.
- The frontend sends same-origin session credentials explicitly and unlock transition is reduced to ~120ms after successful verification.
- If you redeploy with multiple instances, keep one stable `FLASK_SECRET_KEY` value across all instances.


## V22 Secure Page-Load Access
- The website access code is required once for each fresh page load.
- Browser refresh/reload starts a new authorization cycle and asks for the code again.
- Scanning, pair changes, and timeframe changes do not ask for the code again after unlock.
- The access code is never embedded in the frontend.
- `/` and `/premium` are served with no-cache headers and clear the previous page authorization.
- The old frontend backend-information notice was removed from the dashboard.


## V23 Real FX Session + Live Clock Fix
- Weekly FX session logic is anchored to `America/New_York`, not the Render server timezone or visitor timezone.
- Sunday opens at 17:00 New York time; Friday closes at 17:00 New York time. Saturday is closed.
- Monday-Friday are treated as open; broker-specific daily rollovers are not incorrectly shown as a full market closure.
- `/api/market-status` now returns canonical server UTC time, New York session time, next weekly close while open, and next weekly open while closed.
- The dashboard shows a live local clock and a real weekly-close/open countdown.
- The premium scan is no longer blocked by the old incorrect weekly-session calculation.
- After the weekly open, the engine waits for a genuinely completed fresh-session candle and automatically retries instead of forcing a manual refresh.
- No fake candle or fake direction is generated when live validated data is unavailable.
